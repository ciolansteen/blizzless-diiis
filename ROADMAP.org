* Overview
Self-hosted Diablo III private server (blizzless-diiis) via Docker Compose pe Arch Linux / Docker Desktop (WSL2).
Scopul acestui document: track fix-urile necesare sa porneasca si sa functioneze corect in Docker,
cu ochii si pe ce trimitem eventual upstream.

| Component       | Tech                               |
|-----------------+------------------------------------|

| Auth flow       | REST HTTP :83 + Battle TLS :1119   |

*** Solutia finala (clean)
Pattern: fisierele originale =.config= raman identice cu upstream (=Server=localhost=).
Template-urile =.config.template= contin placeholders, sunt procesate de =entrypoint.sh= la startup.

Fisiere noi:
- =docker/entrypoint.sh= :: substituie env vars in toate config-urile via =envsubst= la startup
- =src/DiIiS-NA/database.Account.config.template= :: placeholder version a Account config
- =src/DiIiS-NA/database.Worlds.config.template= :: placeholder version a Worlds config
- =.env.template= :: template pentru toate variabilele de mediu
- =.env= :: valori reale (gitignored)

Modificari fisiere existente:
- =Dockerfile= :: instaleaza =gettext-base= (pentru =envsubst=), COPY template-uri, ENTRYPOINT
- =docker-compose.yml= :: adauga =env_file: .env=
- =.gitignore= :: adauga =.env=

*** Continut fisiere

**** docker/entrypoint.sh
#+BEGIN_SRC sh
#!/bin/sh
set -e

DB_HOST="${DB_HOST:-localhost}"
DB_PORT="${DB_PORT:-5432}"
DB_USER="${DB_USER:-postgres}"
DB_PASSWORD="${DB_PASSWORD:-postgres}"

BIND_IP="${BIND_IP:-0.0.0.0}"
REST_IP="${REST_IP:-0.0.0.0}"
PUBLIC_IP="${PUBLIC_IP:-127.0.0.1}"

for cfg in database.Account.config database.Worlds.config; do
    envsubst < "/app/${cfg}.template" > "/app/${cfg}"
done

envsubst < /app/config.ini.template > /app/config.ini

exec ./Blizzless
#+END_SRC

**** src/DiIiS-NA/database.Account.config.template
Connection string cu placeholders (unica diferenta fata de original):
: Server=${DB_HOST};Port=${DB_PORT};Database=diiis;User ID=${DB_USER};Password=${DB_PASSWORD}

**** src/DiIiS-NA/database.Worlds.config.template
: Server=${DB_HOST};Port=${DB_PORT};Database=worlds;User ID=${DB_USER};Password=${DB_PASSWORD}

**** .env.template
#+BEGIN_SRC sh
# Database connection (used by entrypoint.sh at container startup)
DB_HOST=diiis-na-db
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=postgres

# PostgreSQL container (must match DB_* above)
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_DB=diablo

# Server IP bindings
# BIND_IP: interface the server listens on (0.0.0.0 = all interfaces, required for Docker)
BIND_IP=0.0.0.0
# REST_IP: interface the REST login server listens on
REST_IP=0.0.0.0
# PUBLIC_IP: IP advertised to the D3 client (must be reachable from client machine)
PUBLIC_IP=127.0.0.1
#+END_SRC

**** Dockerfile (sectiunea runtime, dupa FROM aspnet:7.0)
#+BEGIN_SRC dockerfile
# envsubst (from gettext-base) is used by entrypoint.sh to substitute env vars into config files
RUN apt-get update && apt-get install -y --no-install-recommends gettext-base && rm -rf /var/lib/apt/lists/*

WORKDIR /app

# Copy the published application from the build stage
COPY --from=build /app/publish .

# Copy DB config templates (envsubst generates .config files at startup)
COPY src/DiIiS-NA/database.Account.config.template /app/database.Account.config.template
COPY src/DiIiS-NA/database.Worlds.config.template /app/database.Worlds.config.template

# Copy config template (envsubst will generate config.ini at startup)
COPY src/DiIiS-NA/config.ini.template /app/config.ini.template

# Copy entrypoint script
COPY docker/entrypoint.sh /app/entrypoint.sh

EXPOSE 1345 1119 83 2001 9800 9100

ENTRYPOINT ["/bin/sh", "/app/entrypoint.sh"]
#+END_SRC

**** docker-compose.yml (diiis-na-server service)
#+BEGIN_SRC yaml
diiis-na-server:
  build:
    context: .
    dockerfile: Dockerfile
  container_name: diiis-na-server
  stdin_open: true
  env_file: .env
  environment:
    - DOTNET_EnableDiagnostics=0
  ports:
    - 83:83
    - 1119:1119
    - 1345:1345
    - 2001:2001
    - 9800:9800
    - 9100:9100
  depends_on:
    db:
      condition: service_healthy
#+END_SRC

** DONE Fix 2: CPU 100% pe Server Idle                               :docker:
CLOSED: [2026-03-26] -- workaround in compose, fix proper in Fix 5
Gitea: https://git.ciolan.net/Gaming/blizzless-diiis/issues/2

Root cause: =Console.ReadLine()= in Docker (stdin=EOF, fara TTY) returneaza =null= instant.
Main loop face =continue= pe null -> spin loop infinit (~1.3M read() syscalls/sec, un core complet).

Investigatie:
1. Round 1 :: =AnsiLog= cu =MinimumLevel=MethodTrace= -> sute log/sec -> fix nivel =Info=
2. Round 2 :: CLR debug pipes in =/tmp= busy-polled -> fix =DOTNET_EnableDiagnostics=0=
3. Round 3 :: =ReadLine()= null spin -> fix =stdin_open: true= in compose

*** Solutia finala (workaround)
In =docker-compose.yml= pe serviciul =diiis-na-server=:
#+BEGIN_SRC yaml
stdin_open: true
environment:
  - DOTNET_EnableDiagnostics=0
#+END_SRC

Workaround -- fix proper in sursa (Fix 5).

* Note Tehnice

** REST Auth Flow
D3 -> port 1119 (TLS) -> server trimite URL =http://PUBLIC_IP:83/battlenet/login=
-> D3 GET (form) -> POST (credentiale) -> ticket -> verificat pe 1119.
Daca REST nu raspunde sau form e gol -> disconnect imediat, eroare 14003.

** Thread Profiling fara strace (in container)
#+BEGIN_SRC bash
cat /proc/1/task/<TID>/stat   # utime+stime jiffies
cat /proc/1/task/<TID>/wchan  # 0 = running (nu blocheaza)
cat /proc/1/task/<TID>/io     # syscr = numar read() calls
#+END_SRC
Semnatura spin loop: =wchan=0=, =stime= creste, =syscr= ~1.3M/sec, =rchar=33 bytes total.

** DOTNET_EnableDiagnostics=0
Elimina =clr-debug-pipe-*= si =dotnet-diagnostic-*= din =/tmp=.
Recomandat pentru productie / containere.

** envsubst vs sed
Initial folosit =sed -i= cu regex pentru substituire valori in XML.
Inlocuit cu =envsubst= (pachetul =gettext-base=) -- mai simplu, fara regex fragil,
lucreaza direct cu =${VAR}= placeholders din fisiere.
Pattern adoptat: fisierele originale raman identice cu upstream,
=.template= variants contin placeholders, procesate la container startup.
